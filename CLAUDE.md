# ROYEXA

Antes de hacer cualquier cosa, lee `odd/tasks/mvp.md` completo. Sus «Reglas para cada sesión» mandan:
toma la primera tarea sin marcar, en orden; una rama y un pull request por tarea; pruebas primero
(`uv run pytest -m ""` desde `backend/`); marca la casilla y anota la evidencia en el mismo PR.

- Requisitos y criterios de aceptación: `docs/01-requisitos/requisitos.md` (no borrar ni renumerar RF, RN, CA, EC).
- Código e identificadores en inglés; documentos en español.
- Fuera de alcance: app nativa, operación sin conexión, varias empresas, proveedor real de notificaciones, nube de pago.
- Si falta una decisión de producto, déjala en «Preguntas abiertas» y detente.
- Rama de trabajo de una sesión en la nube: la que indique la sesión; no abras PR sin que el usuario lo pida.
