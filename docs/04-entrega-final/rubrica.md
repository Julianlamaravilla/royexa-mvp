# Rúbrica de evaluación — Entrega 4

| Criterio | Peso | Pregunta de evaluación |
|---|---:|---|
| Producto funcional y alcance final | 25 % | ¿La solución completa el flujo principal y las capacidades Must viables, protege reglas relevantes y produce el resultado de negocio comprometido? |
| Arquitectura consolidada y coherencia | 15 % | ¿Las vistas C4, fronteras, dependencias, componentes y código representan una solución coherente y vigente? |
| Diseño interno, SOLID y patrones | 15 % | ¿Las responsabilidades, contratos y patrones responden a problemas reales, reducen acoplamiento o variación y evitan sobreingeniería? |
| Integración y razonamiento distribuido | 10 % | ¿La frontera externa está aislada, es demostrable y contempla latencia, indisponibilidad o respuesta inválida sin exigir microservicios injustificados? |
| Evaluación arquitectónica, ADR y trade-offs | 15 % | ¿La evidencia evalúa al menos dos escenarios, actualiza decisiones y hace explícitos riesgos, deuda y consecuencias? |
| Pruebas y evidencia | 10 % | ¿Las pruebas cubren flujo principal, reglas, alternativa e integración, son reproducibles y verifican resultados observables? |
| Reproducibilidad y calidad de la entrega | 10 % | ¿Los comandos, rutas, datos y evidencias funcionan desde un clon limpio y no contienen secretos ni artefactos innecesarios? |
| **Total** | **100 %** | |

## Condiciones que limitan la calificación

- Si el proyecto no puede ejecutarse por falta de instrucciones o configuración entregada, los criterios de producto, pruebas y reproducibilidad se evaluarán únicamente con la evidencia verificable disponible.
- Si el equipo no identifica el commit o etiqueta evaluable, se tomará el último commit anterior al cierre que se pueda identificar de forma inequívoca.
- Un diagrama que contradiga el código no se considerará evidencia de arquitectura vigente.
- Un patrón nombrado pero no presente en el código no se evaluará como aplicado.
- Si una integración externa impide la demostración y el equipo no provee sustituto controlado, el escenario se considerará no reproducible.
- Las funcionalidades no trazadas a requisitos ni demostradas no compensan funcionalidades Must incompletas.
