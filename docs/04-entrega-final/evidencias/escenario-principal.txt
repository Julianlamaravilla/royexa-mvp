Escenario principal y alternativas por HTTP — ROYEXA, Entrega 4
================================================================
Fecha: 2026-11-16 (lunes, día de cobranza en UTC). Rama entrega-4-final @ 12c2f1e.
Arranque (desde backend/; modo sin base de datos, datos de demostración sembrados al arrancar,
despacho manual para que el orden de los pasos sea explícito):
  ROYEXA_DISPATCH_SECONDS=0 uv run uvicorn royexa.main:app --port 8766
Con ROYEXA_LEDGER_URL los mismos casos de uso escriben en PostgreSQL; ese camino lo cubren las
variantes [postgres] de las pruebas verticales (resultado-pruebas.txt).
Cada petición lleva 'Authorization: Bearer <token>' de POST /v1/auth/login con cobrador-1, admin-1
(contraseñas públicas demo-<usuario>-royexa); los tokens se omiten y de cada respuesta se
muestran solo los campos relevantes. El código de confirmación se enmascara.

Resumen: desembolso de 100,00 confirmado con el código (20 cuotas de 6,00, caja 1.000.000,00 ->
999.900,00); pago parcial de 3,00 -> 19,5 cuotas restantes de 20 (RN-01); cierre con 578,00
entregados frente a 603,00 esperados -> descuadre -25,00 visible para el administrador (RN-02,
CA-03, CA-13). Alternativas: cierre con visitas pendientes rechazado (CA-04), pago tras el cierre
rechazado (RN-02) y autoaprobación rechazada con el intento registrado (RN-06, EC-02).

## 1. El cobrador solicita un desembolso de 100,00 a 20 cuotas para cliente-1 (RF-03, RN-05)
$ POST /v1/disbursements
  body: {"client_id":"cliente-1","amount_cents":10000,"term_days":20,"installment_count":20}
  HTTP 201
  {"id": "7d32cd3a-5aa1-45c4-b8f5-4215c8e6a8ad", "status": "SOLICITADO", "client_id": "cliente-1", "requested_by": "cobrador-1", "amount_cents": 10000}

## 2. El administrador admin-1 aprueba; el dinero aún no se mueve (RN-03, RN-06)
$ POST /v1/disbursements/7d32cd3a-5aa1-45c4-b8f5-4215c8e6a8ad/approve
  body: {}
  HTTP 200
  {"id": "7d32cd3a-5aa1-45c4-b8f5-4215c8e6a8ad", "status": "APROBADO", "requested_by": "cobrador-1", "approved_by": "admin-1"}

$ GET /v1/cash-boxes/cobrador-1
  HTTP 200
  {"balance_cents": 100000000}

## 3. Despacho de avisos: el notificador simulado (EXT-05) entrega el código al cliente
$ POST /v1/notifications/dispatch
  HTTP 200
  {"attempted": 1, "sent": 1}

  Salida del servidor: [EXT-05] to=cliente-1 kind=CODIGO_CONFIRMACION disbursement=7d32cd3a-5aa1-45c4-b8f5-4215c8e6a8ad payment=None payload={'code': '<código dictado por el cliente>'}

## 5. Alternativa: cerrar la caja con visitas pendientes se rechaza (CA-04, RN-02)
